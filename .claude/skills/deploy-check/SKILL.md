---
description: 本番デプロイ前の準備状況をチェックしてレポートする
---

本番デプロイ前に必要な確認をすべて実施し、チェックリスト形式でレポートします。

## 手順

以下のチェックを順番に実行する。

### 1. TypeScript 型チェック

```bash
npx tsc --noEmit 2>&1 | tail -5
npx tsc --project tsconfig.server.json --noEmit 2>&1 | tail -5
```

### 2. ビルド確認

```bash
npm run build 2>&1 | tail -20
```

### 3. 環境変数テンプレートの存在確認

`.env.example` または `.env.sample` があるか確認する。なければ作成を提案する。

必要な環境変数:
- サーバー: `PORT`, `NODE_ENV`, `CLIENT_URL`
- クライアント: `VITE_API_URL` (本番サーバーURL)

### 4. デプロイ設定ファイルの確認

以下のファイルが存在するか確認:
- `railway.toml` または `render.yaml` (バックエンドデプロイ)
- `vercel.json` または `netlify.toml` (フロントエンドデプロイ)

### 5. レポート出力

```
## デプロイ準備チェックリスト

### ビルド
- [ / ✅ / ❌] TypeScript (フロントエンド): エラーN件
- [ / ✅ / ❌] TypeScript (サーバー): エラーN件
- [ / ✅ / ❌] クライアントビルド: 成功 / 失敗
- [ / ✅ / ❌] サーバービルド: 成功 / 失敗

### 設定
- [ / ✅ / ❌] .env.example: 存在する / なし
- [ / ✅ / ❌] バックエンドデプロイ設定: あり / なし
- [ / ✅ / ❌] フロントエンドデプロイ設定: あり / なし

### 次のアクション
1. ...（未完了の項目への対応手順）
```

## 推奨デプロイ構成

| 役割 | サービス | 理由 |
|---|---|---|
| バックエンド | Railway または Render | WebSocket対応、無料枠あり |
| フロントエンド | Vercel または Netlify | Viteビルド対応、CDN配信 |

デプロイ設定ファイルが存在しない場合は、作成を提案する。

## デプロイ時の注意

- フロントエンドビルド時に `VITE_API_URL` を本番サーバーURLに設定する必要がある
- WebSocket は `wss://` (HTTPS環境では必須) を使用する
- CORS 設定でフロントエンドのドメインを許可する (`server/index.ts`)
